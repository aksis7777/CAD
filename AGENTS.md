# Инструкции для моделей

Нормативные бизнес- и архитектурные решения находятся только в [PDM_RULES.md](PDM_RULES.md). При противоречии этот файл приоритетен; документация ниже только объясняет его. До архитектурных изменений прочитать `PDM_RULES.md`, `ARCHITECTURE.md`, `PROJECT_STATE.md` и `ROADMAP.md`.

## Роли

- **Astra:** сложные архитектурные выборы, сложный анализ и проектирование крупных изменений. Даёт решение и инструкции, основной код не пишет.
- **Sol:** задачи средней сложности, декомпозиция, анализ кода, инструкции Luna и обязательное ревью её реализации. Основной код не пишет.
- **Luna:** код, тесты, рефакторинг по плану, документация и рутинные изменения. Не принимает существенные архитектурные решения самостоятельно.

## Рабочий процесс

- Простое: `Luna → результат`.
- Среднее: `Sol → план → Luna → реализация → Sol → ревью`.
- Архитектурное: `Astra → решение → Sol → план → Luna → реализация → Sol → ревью`.
- При серьёзном архитектурном замечании Sol эскалирует Astra; Luna не угадывает при недостатке решений.

Качество важнее экономии. Не использовать более дорогую модель, если задача надёжно решается дешёвой. Паттерн или архитектурное поведение, не закреплённое в `PDM_RULES.md`, сначала обсудить и зафиксировать там до написания соответствующего кода.

## Документация и изменения

Поддерживать `PDM_RULES.md`, `ARCHITECTURE.md`, `PROJECT_STATE.md`, `ROADMAP.md` актуальными. `PDM_RULES.md` — единственный нормативный источник; остальные документы ссылаются на него и не вводят отдельные обязательные правила. Обновлять состояние и дорожную карту вместе с выполненной работой. Не создавать дублирующие правила в коде или документах.
