# Состояние проекта

Нормативный источник: [PDM_RULES.md](PDM_RULES.md). План следующих шагов — в [ROADMAP.md](ROADMAP.md).

## Сейчас

- Создан solution с API, Avalonia Desktop, Contracts, Domain, Storage, шестью проектами модулей и тестовыми проектами; PostgreSQL-интеграционный проект расположен отдельно от solution.
- Добавлен запускаемый API с `GET /health`, подключением контроллеров модулей и MediatR. Desktop содержит Avalonia shell, HTTP-клиент, основные экраны объектов/версий/состава/импорта и страницу фоновых задач.
- Domain содержит правила версии и состояния, проверки атрибутов и состава, а также общий поиск циклов действующего графа. Эти правила используются импортом и ручными командами изменения версий.
- Storage содержит EF Core/Npgsql mapping, ключи/ограничения, composite FK текущей версии, scoped DbContext с токеном конкурентности и проверкой точности массы. В репозитории находятся `InitialCreate`, `AddImportJournalAndStandardName` и `AddBackgroundTasks`; все три миграции применены на временной PostgreSQL 17. Постоянная пользовательская база не настраивалась.
- Импорт реализован от HTTP до Storage: загрузка отдельных CAD JSON-файлов, Factory/Iterator/JSON reader, проверка документов и графа, частичное принятие пакета, создание версий, отчёт, повторный импорт, журнал идемпотентности, сериализация изменения графа и согласование файлов с транзакцией. `ImportSourceRecovery` возвращает диагностики, восстанавливает/очищает источники и пропускает активные upload leases; API вызывает его при запуске и планирует повторы через фоновую задачу с persistent расписанием.
- Проверены оба полных набора `cad-export` и `cad-export-v2` по 45 файлов. В `cad-export` принято 35, отклонено 10, одно предупреждение о пустой массе. После утверждения текущих версий импорт `cad-export-v2` создал версии для двух объектов и оставил 33 принятых документа без изменений. Повторная отправка того же `import-id` возвращает прежний отчёт; конкурентные запросы с одним ID не дублируют запись.
- Финальная проверка: `dotnet build MiniPdm.sln` завершился с 0 warnings и 0 errors; 129 solution tests (79 Modules, 33 Storage, 17 Desktop) прошли без пропусков. Ещё 11 PostgreSQL tests прошли на заполненной временной БД — всего 140 без пропусков. EF Core `has-pending-model-changes` сообщил, что новых миграций нет.
- Реализованы чтение дерева через `ICompositionReadQuery` и один PostgreSQL recursive CTE, endpoint состава, а также endpoint расчётов массы/спецификации. Плоские вхождения сохраняют повторные появления с разными путями. Расчёт выполняется чистой доменной логикой по одному результату CTE; неизвестная масса листа сохраняет известное количество, но даёт null для его масс. Переполнение количества даёт null quantity. Любая диагностика приводит к `TotalMassKg = null` и `IsComplete = false`, известные строки спецификации остаются. Интеграционные PostgreSQL-тесты в `tests/MiniPdm.Postgres.Tests` требуют `PDM_TEST_POSTGRES_CONNECTION`: read-query тесты откатывают транзакции, concurrent-write тесты очищают только созданные ими случайные fixtures; таблицы не очищаются и чужие данные не затрагиваются.
- Реализованы и проверены по HTTP поиск и карточка объектов через `GET /api/objects` и `GET /api/objects/{id}`. Поиск — буквальный регистронезависимый поиск по обозначению, имени текущей действующей версии и имени StandardPart; `%`, `_` и `\\` экранируются. Пагинация принимает `offset >= 0`, `limit 1..100`, `search <= 512`, определяет `HasMore` дополнительной строкой и не делает `COUNT`. Карточка по умолчанию выбирает current version, по `?version=N` может показывать любую историческую версию, включая Cancelled. Нет текущей версии — `200` с null selected version и `NoCurrentVersion`; отсутствующий объект или запрошенная версия — `404`, пустой GUID и неположительная версия — `400`. DTO карточки содержит идентичность, current pointer и concurrency token; выбранная версия полная с `SourceReference`, история — только metadata. Для Assembly масса в карточке null и берётся из calculation endpoint. Запросы используют no-tracking projections, без полной загрузки сущностей или чтения файлов.
- Реальная HTTP-проверка Objects на временной PostgreSQL 17 подтвердила 35 уникальных результатов в пяти страницах по 7, case-insensitive поиск кириллицей по колесам и стандартным болтам, буквальный поиск `%`, статус-коды для неверной пагинации/поиска/версии и пустого GUID. Все 35 текущих карточек имели верные token/current pointer; имя StandardPart совпало в header/selected version; масса Assembly null. Тестовый fixture также подтвердил read-only чтение объекта без current version и Cancelled historical version.
- Реализованы HTTP-команды клонирования версии, изменения состояния, атрибутов и состава. Они используют общий доменный planner и `IVersionWritePersistence` с общей advisory lock, проверкой expected token после блокировки, проверкой будущего графа и атомарной записью. Предыдущая полная сборка и тесты прошли.
- HTTP smoke-проверка на временной PostgreSQL подтвердила `cad-export` (35 принято, 10 отклонено, 1 предупреждение), начальную массу `РДЦЛ.304112.000` 98.804 кг и импорт `cad-export-v2` (2 `NewVersion`, 33 `Unchanged` после утверждения 35 текущих версий). Проверены clone, token и immutability conflicts, атрибуты/валидация, BOM merge/removal, self-cycle и циклический fallback, cancelled-only object с null current и восстановлением clone, а также конкурентный clone (201/409). Скрипт — `/tmp/pdm-versions-http-smoke.py`.
- На временной PostgreSQL 17 применены все три миграции, включая `AddBackgroundTasks`. HTTP smoke подтвердил startup recovery (удалена собственная orphan-папка), ручной запуск `202` с результатом `Succeeded`, сериализацию 12 одновременных ручных запросов при удерживаемой graph lock (1 `202`, 11 `409`), изменение интервала 1440→7→8→1, повтор через фактическую минуту и удаление следующей orphan-папки. После перезапуска API GET вернул сохранённый интервал 1; startup recovery завершился, тестовый интервал возвращён к 7. Успешные CAD-исходники сохранены. Временный API/PG окружение очищено; постоянная пользовательская база не использовалась.
- Avalonia UI прошёл headless capture и проверки доступности/биндингов: актуальный InWork editor доступен, Approved editor заблокирован, количество для состава доступно. VM тесты покрывают stale selection, 409 с сохранением введённого значения и повтор импорта. Нативный GUI запуск с реальным display server не выполнялся.
- Добавлена Docker Compose схема с PostgreSQL 17, одноразовым EF Core migration bundle, ASP.NET Core API и Avalonia Desktop через noVNC. Корневой URL сразу показывает единственное окно Avalonia; отдельной browser import page нет, API не раздаёт static files и не публикует host port. Вызов кнопки импорта в контейнерном Avalonia Desktop открывает небольшой noVNC overlay: пользователь явным нажатием запускает browser directory picker и передаёт CAD файлы во встроенный picker bridge. Фильтрация `.a3d`/`.m3d`, лимиты и проверка одинаковых basenames выполняются в расширении; API upload, отчёт и безопасный повтор остаются в текущем Avalonia import flow. Папку Mac не требуется копировать в контейнер. Из-за browser user activation нужен один клик в overlay после нажатия кнопки в Avalonia. DB/source files хранятся в named volumes. Порт Desktop опубликован только на `127.0.0.1`. В Desktop-образе задана UTF-8 locale и установлен DejaVu для кириллицы. Chromium проверил JS расширение с подменённым noVNC DOM через реальный Kestrel bridge, ImportViewModel, API и свежую временную PostgreSQL: 35 принятых, 10 отклонённых, одно предупреждение, 45 строк отчёта; временные staging-файлы удалены. Полный GUI noVNC в Docker-контейнере этой проверкой не покрывался; образы нужно пересобрать и проверить целиком.
- HTTP проверка прямого BOM выбранной версии подтвердила A1 с одним ребёнком и A2 с пустым BOM. Ответ сохранил token объекта; запрос не изменил историю, текущую версию или действующее дерево.
- Оба новых endpoint проверены по HTTP на временной PostgreSQL 17 после импорта `cad-export` (35 принято, 10 отклонено, одно предупреждение). Для `РДЦЛ.304112.000` расчёт вернул 98.804000 кг, 33 вхождения дерева и 25 строк спецификации; все количества совпали с независимым расчётом `Decimal` по CAD. Для `РДЦЛ.304112.900` с `Прокладка маслоуказателя` без массы ответил `MissingMass`, `TotalMassKg = null`, `IsComplete = false`; количество прокладки известно и равно 1, её единичная и строковая массы null. Несуществующий ID дал 404, пустой GUID — 400, объект без текущей версии — 200 с `NoCurrentVersion` и null итоговой массой. Постоянная база пользователя не использовалась; временный PostgreSQL-контейнер остановлен и удалён после проверок.
