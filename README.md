# Mini-PDM

Мини-PDM на .NET 10: API на ASP.NET Core Controllers и MediatR, PostgreSQL через EF Core, Desktop на Avalonia/MVVM. Реализованы CAD-импорт, поиск и карточка объектов, версии и состав, расчёты массы/спецификации и страница управления фоновой очисткой. Desktop обращается к API по HTTP и показывает `SourceReference` как серверную ссылку; загрузка и открытие исходного файла из Desktop пока не реализованы.

## Быстрый запуск через Docker Compose

Установите Docker Desktop и клонируйте репозиторий. Из его папки выполните одну команду:

```sh
docker compose up -d --build
```

Первый запуск собирает образы, поднимает PostgreSQL, автоматически применяет EF Core миграции, затем запускает API и Avalonia Desktop через noVNC. Сборка может занять несколько минут. Откройте <http://localhost:8080> — там сразу отображается единственное окно Avalonia. API работает внутри Compose network и отдельным портом на компьютере не публикуется.

В Desktop-контейнере включена UTF-8 locale и установлен шрифт DejaVu для корректного отображения кириллицы в заголовке Fluxbox/noVNC.

Проверка Compose-конфигурации и migration bundle прошла; bundle применил три миграции к свежей PostgreSQL 17, повторный запуск не менял схему. Полный Compose build ранее остановился с HTTP 403 от Docker Registry; локально `docker compose build desktop` завершился успешно, пересоздан только Desktop-контейнер, API и PostgreSQL остались здоровы, named volumes сохранены.

Импорт запускается кнопкой «Импортировать папку» в Avalonia. В Docker-режиме появится небольшой диалог поверх того же окна: нажмите «Выбрать папку на компьютере», чтобы открыть системный выбор папки Mac. Браузер отправляет `.a3d` и `.m3d` файлы, включая вложенные папки, встроенному picker bridge; отчёт и повторы отображаются в Avalonia. Переносить набор в репозиторий или контейнер не требуется. Повторяющиеся имена CAD-файлов запрещены, поскольку сборки ссылаются на детали по имени. Ограничения: максимум 1000 CAD-файлов, 8 MiB на файл и 64 MiB на запрос. База и сохранённые исходники остаются в Docker volumes после перезапуска. Чтобы изменить порт Desktop или пароль локальной базы, скопируйте `.env.example` в `.env` и отредактируйте значения. `PDM_DESKTOP_PORT` меняет порт noVNC. Поменяйте пароль `POSTGRES_PASSWORD` перед использованием вне своего компьютера.

Если диалог выбора папки перестал появляться, перезапустите Desktop-контейнер и обновите страницу браузера:

```sh
docker compose up -d --build --no-deps desktop
```

Это пересобирает и перезапускает только Desktop; базу и сохранённые CAD-файлы удалять не нужно.

Проверить состояние и логи можно командами `docker compose ps` и `docker compose logs -f api desktop migrations`. Остановить приложение: `docker compose down`. Команда `docker compose down -v` удаляет volumes с базой и исходниками.

## Как устроен код

`MiniPdm.Api` — запускаемый ASP.NET Core API, `MiniPdm.Desktop` — приложение Avalonia, `MiniPdm.Contracts` — общие HTTP DTO, `MiniPdm.Common` — типизированные прикладные исключения и `.resx` тексты сообщений, `MiniPdm.Domain` — бизнес-правила, `MiniPdm.Storage` — `PdmDbContext`, EF Core mapping/миграции, DI-регистрация и общий graph lock. Функциональность находится в `src/Modules/MiniPdm.Modules.*`.

В каждом backend-модуле HTTP endpoints собраны в `Controllers`, а CQRS сообщения и их handlers разнесены по `Features/Commands` и `Features/Queries`. Контроллер отправляет сообщение через MediatR, handler вызывает service своего модуля, service работает со scoped `PdmDbContext` через EF Core. Например, поиск объектов находится в `Modules/MiniPdm.Modules.Objects/Services/ObjectReadService.cs`, а редактирование версий — в `Modules/MiniPdm.Modules.Versions/Services/VersionMutationService.cs`. Компоненты saga импорта и singleton фонового координатора используют отдельные scoped database services, чтобы сохранять свежие границы DbContext.

Общие входные и бизнес-ошибки используют готовый текст из `MiniPdm.Common` ресурсов. API централизованно превращает соответствующие типизированные исключения в `ProblemDetails`; структурированные ответы доменных команд сохраняют свои коды и поля. Формат сообщений и границы обработки описаны в [PDM_RULES.md](PDM_RULES.md).

Это обзор основных частей и связей проекта, а не утверждение, что в README задокументирован каждый файл или класс. Требования к XML-документации публичных типов, членов и параметров, включая отдельное описание каждого объявленного свойства, приведены в `PDM_RULES.md`. Для positional record описание параметра конструктора не заменяет summary свойства: конструктор сохраняет исходную сигнатуру, а свойство явно объявляется с `init`.

## PostgreSQL и миграции

Задайте connection string через переменную окружения `PDM_CONNECTION_STRING`; секрет не хранится в репозитории. ASP.NET Configuration также принимает `ConnectionStrings:PdmDatabase`. Пока физическая схема PostgreSQL не выбрана, таблицы используют техническую схему PostgreSQL по умолчанию `public`; это не фиксирует выбор отдельной схемы проекта.

EF CLI установлен локальным tool manifest:

```sh
dotnet tool restore
dotnet ef database update --project src/MiniPdm.Storage --startup-project src/MiniPdm.Storage --context PdmDbContext
```

Миграции `InitialCreate`, `AddImportJournalAndStandardName` и `AddBackgroundTasks` находятся в репозитории. Проверки миграций выполнялись на временной PostgreSQL 17; постоянная пользовательская база не настраивалась. Для своей базы примените все три миграции командой `database update`. Для последующих изменений модели создайте миграцию и сохраните её вместе с кодом:

```sh
dotnet ef migrations add AddDescription --project src/MiniPdm.Storage --startup-project src/MiniPdm.Storage --context PdmDbContext --output-dir Migrations
dotnet ef database update --project src/MiniPdm.Storage --startup-project src/MiniPdm.Storage --context PdmDbContext
```

При создании объекта сначала сохраните его с `CurrentVersionId = null`, затем добавьте его версии и в той же явной транзакции назначьте текущую версию. Составной FK проверяет, что указатель ведёт на версию этого же объекта.

### Запуск API и Desktop без Docker

Настройте `PDM_CONNECTION_STRING` (либо ASP.NET configuration `ConnectionStrings:PdmDatabase`), затем примените миграции и запустите API на адресе, который использует Desktop:

```sh
export PDM_CONNECTION_STRING='Host=localhost;Database=mini_pdm;Username=...;Password=...'
dotnet tool restore
dotnet ef database update --project src/MiniPdm.Storage --startup-project src/MiniPdm.Storage --context PdmDbContext
dotnet run --project src/MiniPdm.Api --urls http://localhost:5000
```

В другом терминале запустите Desktop:

```sh
PDM_API_BASE_URL=http://localhost:5000 dotnet run --project src/MiniPdm.Desktop
```

`PDM_API_BASE_URL` по умолчанию равен `http://localhost:5000`. API при запуске создаёт запись задачи восстановления источников; интервал по умолчанию — 1440 минут. Расписание и последний результат хранятся в PostgreSQL, менять интервал и запускать задачу можно со страницы «Фоновые задачи». `GET /health` проверяет, что API отвечает.

Объекты и версии представлены раздельно: имя и материал изменяемы на уровне версии, масса хранится в килограммах с точностью `numeric(18,6)`, обозначение и стандартное наименование задают идентичность объекта. ## Поиск и карточка объекта

`GET /api/objects?search=&offset=0&limit=50` возвращает страницу `Items`, `Offset`, `Limit`, `HasMore`; общее число результатов не вычисляется. `limit` должен быть от 1 до 100, `offset` — неотрицательным, `search` — не длиннее 512 символов. Поиск — регистронезависимое буквальное вхождение подстроки в обозначение, наименование текущей неаннулированной версии или исходное имя стандартного изделия. Символы `%`, `_` и `\` экранируются как обычный текст. Строки сортируются по обозначению (либо имени стандартного изделия), затем по ID для стабильной пагинации. Превышение длины search и неверные границы пагинации возвращают 400.

Элемент страницы содержит `Id`, `Type`, `Designation`, `Name`, `CurrentVersionId`, `VersionNumber`, `State`, `UnitMassKg`, `ConcurrencyToken` и `NoCurrentVersion`. У сборок `UnitMassKg` всегда null; используйте endpoint расчётов для массы сборки. Для объекта без текущей версии поля текущей версии остаются null, а `NoCurrentVersion` равен true.

`GET /api/objects/{id}?version=N` возвращает заголовок объекта, выбранную версию и список версий. Параметр `version` необязателен, должен быть положительным числом и выбирает историческую версию; аннулированную версию можно просматривать. Без него выбирается текущая версия. Заголовок содержит идентичность, `CurrentVersionId` и `ConcurrencyToken`; `SelectedVersion` содержит ID, номер (`Version`), состояние, атрибуты и `SourceReference`, а `Versions` — только ID, номер, состояние и признак текущей версии. Для сборки масса выбранной версии равна null, поскольку она вычисляется из состава. Пустой GUID и неположительный номер версии дают 400; неизвестный объект или запрошенная версия дают 404. Известный объект без текущей версии при запросе по умолчанию возвращает 200 с `SelectedVersion: null`, `ErrorCode: "NoCurrentVersion"` и описанием в `Error`.

Оба чтения используют `AsNoTracking` и DTO-проекции, без загрузки файлов с диска. Карточка читает атрибуты только выбранной версии, а историю — в виде метаданных.

Search и card endpoints проверены по HTTP на временной PostgreSQL 17. После импорта набора с 35 допустимыми объектами пагинация с `limit=7` вернула 35 разных объектов за пять страниц. Поиск `колесо` нашёл два зубчатых колеса, включая `Колесо зубчатое` массой 5.86 кг; `БОЛТ` нашёл два стандартных изделия; поиск буквального `%` вернул пустой список. Все 35 текущих карточек содержали верные concurrency token и current pointer; имя StandardPart было согласовано и в заголовке, и в выбранной версии; масса сборки в карточке была null.

HTTP-валидация чтения подтвердила `400` для неверных limit/offset, search длиннее 512 символов, пустого GUID и `version=0`, и `404` для неизвестного объекта и `version=999`. В отдельном тестовом fixture объект без current version вернул `200` с `NoCurrentVersion` и был помечен `NoCurrentVersion: true` в поиске. Историческая аннулированная версия также была доступна для чтения: fixture для колеса вернул версию 2 (масса 4 кг, историческое имя, отсутствующая ссылка на исходник), сохранив текущую версию 1 с массой 5.86 кг.

## Команды управления версиями

Все изменения требуют `expectedConcurrencyToken` — непустой токен объекта из карточки (`GET /api/objects/{id}`). Успешный ответ возвращает новый `concurrencyToken`; его следует использовать в следующей команде. Сервер берёт общую блокировку графа, затем перечитывает объект и проверяет токен, поэтому конкурирующее устаревшее изменение получает `409` без записи.

- `POST /api/objects/{id}/versions` с `{ "sourceVersion": 2, "expectedConcurrencyToken": "…" }` создаёт следующую версию «В работе», копируя атрибуты, состав и ссылку на исходник выбранной версии. Источником может быть и аннулированная версия; исходный файл не копируется. Успех — `201 Created`.
- `PUT /api/objects/{id}/versions/{version}/state` с `{ "state": "Approved", "expectedConcurrencyToken": "…" }` меняет состояние только по разрешённым переходам. После аннулирования текущей версии указатель переходит к максимальной неаннулированной версии либо становится null.
- `PUT /api/objects/{id}/versions/{version}/attributes` с `name`, `material`, `mass` и `expectedConcurrencyToken` редактирует выбранную версию «В работе», в том числе историческую. Правила полей зависят от типа объекта; идентичность объекта не меняется.
- `PUT /api/objects/{id}/versions/{version}/composition` с массивом `components` (`childObjectId`, `quantity`) и `expectedConcurrencyToken` полностью заменяет состав выбранной версии сборки «В работе». Повторные компоненты объединяются с предупреждением; проверяются количества, существование дочерних объектов и циклы будущего действующего графа.

Для этих команд неверный запрос или доменное значение возвращает `400`, неизвестный объект/версия — `404`, устаревший токен, запрещённое изменение состояния, неизменяемая версия или цикл — `409`. Если результат фиксации неизвестен, API возвращает `503`; перед повтором прочитайте карточку объекта и выясните, применилось ли изменение.

## Чтение состава и расчёты

`GET /api/objects/{objectId}/composition` возвращает плоский список вхождений дерева. `MiniPdm.Modules.Composition.Services.CompositionReadService` выполняет один PostgreSQL recursive CTE через scoped `PdmDbContext`; пути `ObjectPath` и `ParentPath` сохраняют структуру дерева, а повторное вхождение того же объекта в разных ветках остаётся отдельной строкой. `LocalQuantity` — количество непосредственно в строке состава. Отсутствующая текущая версия представлена пустыми полями версии и диагностикой `NoCurrentVersion`; `Cycle` отмечает цикл, обнаруженный защитной проверкой чтения.

`GET /api/objects/{objectId}/calculations` возвращает в одном ответе итоговую массу и плоскую спецификацию, также полученные из одного CTE. Пример формы ответа:

```json
{
  "rootObjectId": "10000000-0000-0000-0000-000000000001",
  "totalMassKg": 12.5,
  "isComplete": true,
  "items": [
    {
      "objectId": "20000000-0000-0000-0000-000000000002",
      "type": "Part",
      "designation": "АБВГ.301245.001",
      "name": "Корпус",
      "material": "Сталь",
      "versionId": "30000000-0000-0000-0000-000000000003",
      "versionNumber": 1,
      "quantity": 2,
      "unitMassKg": 6.25,
      "totalMassKg": 12.5
    }
  ],
  "diagnostics": []
}
```

Массы указаны в килограммах, количество — в штуках. Количество по всем веткам суммируется для плоской спецификации, поэтому деталь, встреченная по двум путям, отражается одной строкой с общим количеством. Масса детали/стандартного изделия берётся из текущей версии; масса сборки рассчитывается по её дочернему составу. Пустая сборка имеет массу 0, корневой объект-деталь учитывается в количестве 1. Неизвестный корневой `objectId` возвращает `404`; известный объект без текущей версии возвращает `200` с ошибкой в диагностиках.

При отсутствии текущей версии компонента, пустой массе, цикле или переполнении количества расчёт добавляет диагностику с `ObjectId` и `ObjectPath`. Любая диагностика означает `totalMassKg: null` и `isComplete: false`; известные строки спецификации остаются в ответе. Если масса листового объекта неизвестна, строка сохраняет известное количество, а `unitMassKg` и `totalMassKg` равны `null`. Если переполнение делает количество неизвестным, `quantity` этой строки равен `null`. Неизвестная масса не скрывает известные количества.

`GET /api/objects/{id}/versions/{version}/composition` читает прямой BOM указанной версии, включая исторический и пустой состав. Это данные для редактора выбранной версии, а не действующее дерево; запрос не меняет current version или состав.

Оба endpoint проверены по HTTP на временной PostgreSQL 17 после импорта `cad-export` (35 принято, 10 отклонено, одно предупреждение). Для сборки `РДЦЛ.304112.000` API вернул массу 98.804000 кг, 33 вхождения дерева и 25 строк спецификации; количества сверены независимым расчётом `Decimal` по CAD-данным. Для объекта `РДЦЛ.304112.900` с деталью `Прокладка маслоуказателя` без массы ответ содержит `totalMassKg: null`, `isComplete: false` и `MissingMass`; известное количество прокладки равно 1, её `unitMassKg` и `totalMassKg` равны `null`. Несуществующий ID возвращает 404, пустой GUID — 400; существующий объект без текущей версии возвращает 200 с `NoCurrentVersion` и `totalMassKg: null`.

## CAD-импорт

Импорт принимает отдельные `.a3d`/`.m3d` JSON-файлы из обычной папки; ZIP-архив не требуется. Используйте новый GUID для новой операции и повторяйте тот же GUID при сетевом повторе: завершённый импорт вернёт сохранённый отчёт без повторной записи.

```sh
curl -X POST "http://localhost:5000/api/imports/10000000-0000-0000-0000-000000000001" \
  -F 'files=@./cad-export/Корпус.m3d' \
  -F 'files=@./cad-export/Редуктор цилиндрический Ц2-160.a3d'
curl "http://localhost:5000/api/imports/10000000-0000-0000-0000-000000000001"
```

Первый запрос отправляет `multipart/form-data`; оба endpoint возвращают JSON-отчёт с результатом по каждому файлу. Ограничения по умолчанию: 1000 файлов, 8 MiB на файл, 64 MiB суммарно и 64 MiB на HTTP-запрос. Корень файлов настраивается параметром `ImportStorage:DataRoot`; по умолчанию используется каталог `data` рядом с API. `ImportStorageOptions` также позволяет настроить лимиты в конфигурации приложения.

Проверенный набор `cad-export` дал 35 принятых и 10 отклонённых файлов, с одним предупреждением о пустой массе детали `Прокладка маслоуказателя`. Отклонения: два файла с невалидным кириллическим обозначением; один повреждённый JSON; две записи с повторяющейся идентичностью; одна сборка с отсутствующей деталью; одна с неположительным количеством; два файла цикла и одна сборка, зависящая от отклонённого циклического компонента. После утверждения текущих версий проверен импорт изменённого набора `cad-export-v2` с новым GUID: он создал две новые версии — масса `Колесо зубчатое` изменилась с 5,86 до 5,92 кг, а количество `Прокладка` в составе `Крышка подшипника` с 3 до 4; остальные 33 принятых документа остались без новой версии. Оба полных набора содержат по 45 файлов.

Фоновая задача `import-source-recovery` выполняет восстановление при запуске API, затем по расписанию с интервалом в минутах (начально 1440); настройки и последний статус/результат хранятся в PostgreSQL. На странице «Фоновые задачи» видны расписание, состояние, даты и результат/ошибка, интервал можно изменить, запускать задачу вручную. HTTP smoke на временной PostgreSQL подтвердил startup cleanup orphan-папки, ручной `202`/`Succeeded`, один принятый запуск и 11 ответов `409` при конкуренции за общую graph lock, фактический запуск через минуту и сохранение интервала после API restart. Успешные CAD-исходники сохранились.

Desktop — оконное Avalonia-приложение и для интерактивного запуска требует графическую сессию. На безоконном сервере используйте API; серверный `SourceReference` отображается как ссылка/текст, загрузка и открытие исходника из Desktop пока не реализованы. Headless проверка Avalonia разметки и рабочих элементов UI прошла; native GUI запуск не проверялся. Детальное состояние приведено в [PROJECT_STATE.md](PROJECT_STATE.md) и [ROADMAP.md](ROADMAP.md).
